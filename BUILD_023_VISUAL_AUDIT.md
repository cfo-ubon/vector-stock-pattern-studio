# Build 023 Visual Audit — Visual Beauty & Premium Art Direction Engine

Real rendered output was inspected, not source code in isolation. All images
referenced below are committed at `reports/build_023/before_after/{before_build022,after_build023}/`
and `reports/build_023/visual_evidence/`, generated by
`app/scripts/build023BeforeAfterEvidence.ts` (70 patterns: 20 Luxury Floral,
10+10 Premium Botanical Floral analogues — `darkBotanical`/`bohoFloral`, this
app's own two closest premiumHero bouquet-composition presets since no single
preset is literally named "Premium Botanical Floral" — 10 Editorial Botanical,
10 Minimal Botanical, 10 strong control `scandinavianOrganic`) at 4 scales
each (full/900px, 512px, 256px, 128px), before (worktree pinned to commit
`525c1d1`, Build 022's final verified state) and after (this branch).

- Branch renamed mid-session from `claude/build-023-premium-bouquet-cohesion`
  to `claude/build-023-visual-beauty-engine` per the user's expanded brief
  (arrived after substantial fragmentation-fix work was already built —

## 1. Method

For each of the 70 samples: rendered the full tile and 3 marketplace-thumbnail
scales, before and after, from the exact same deterministic (styleId, seed)
pair. Cross-referenced against the objective metric pipeline
(`scripts/qualityReport.ts`'s `evaluate`) for `fragmentedSilhouette`,
`deadSpace`, and `absoluteCommercialQuality[V2]` on the identical 70 samples
(`reports/build_023/before_after/{tag}/metrics.json`), so every visual
observation below has a numeric cross-check, not just impression.

## 2. What this build actually changed (carried forward from the
   fragmentation-focused work already substantially built before this
   broader brief arrived) vs. what it did NOT touch

**Changed** (all gated to `params.premiumHero === true`, verified to be a
strict no-op for every other style — see Section 5):
- `engine/clusterEngine.ts` / `layouts/bouquet.ts` / `layouts/heroScatter.ts`:
  `anchorSpacingMultiplier` (2.0x for premiumHero) — widens spacing
  *between* cluster anchors so companions don't collide with a
  neighboring cluster's hero on the silhouette grid.
- `engine/bouquetSpatialGraph.ts` (new): mirrors the critic's own
  connectivity grid, plus `reserveClusterCompanions` (guarantee at least
  one surviving companion per hero cluster when the node-budget thinning
  pass runs).
- `engine/repairPass.ts` (new): deterministic, bounded (max 3 iterations,
  `richnessBudget`-capped) pull of stray cluster members toward their
  anchor before thinning.
- `engine/fragmentedSilhouetteV2.ts` (new): additive, cluster-aware
  diagnostic (does not replace or suppress `critic/visualAnalysis.ts`'s
  existing detector).
- `engine/bouquetSpine.ts` (new): wires the previously-built-but-unused
  `clusterEngine.ts` `buildClusterStem` into actual rendering — draws a
  real connective stem between a hero and its close surviving companions.
  **Found and fixed during this audit**: an early version drew a stem to
  *any* surviving companion regardless of distance, which — combined with
  the wider anchor spacing above — produced a bare, ugly line crossing
  large empty background (see Section 3, Finding V-1). Capped to
  `motifSize * 2.2` reach; beyond that, no connector is drawn at all.
- **Found and fixed during this audit**: `applyBouquetRepairPass` and
  `reserveClusterCompanions` were being called for *any* placement list
  with a `clusterId` (which `buildClusterPlacements` tags unconditionally),
  not only for `premiumHero` styles — an unintended scope leak. Measured
  as a real, small regression on `scandinavianOrganic` (a non-premium
  "strong control" preset: commercial score 86.40 -> 85.00 before the
  fix). Both call sites are now explicitly gated to `params.premiumHero`;
  re-measured after the fix: 86.40 -> 86.30 (residual noise-level, not a
  regression) — see Section 5.

**NOT changed in this build** (the brief's Steps 5-11: flower-family-specific
anatomy, leaf/branch families, a dedicated depth-layering engine, an
explicit art-direction data model, palette-role reassignment, product-specific
composition rules, visual-rhythm/repetition detectors). This is the honest,
material gap between this build's real scope and the brief's full ask — see
Section 6 (Known Limitations) and the final report's verdict rationale.

## 3. Findings, by defect category (with exact numbers and file/function
   references where the responsible mechanism is identified)

### V-1. Disconnected stem rendered as a bare, ugly line across empty background (FIXED, this audit)
- **Where**: `app/src/engine/bouquetSpine.ts`, first implementation.
- **Evidence**: `darkBotanical@m22-2`, pre-fix "after" render, top-left
  quadrant — a single thin diagonal line spans roughly 1/4 of the tile
  width connecting a hero flower to a companion, over completely empty
  background, with no other visual context to make it read as a stem.
- **Root cause**: the anchor-spacing fix (widening cluster spacing to
  fix fragmentation) increases the real distance between a hero and its
  surviving companion; a literal, unconditional stem line at that
  distance reads as a broken scaffold, not a bouquet stem.
- **Fix**: `MAX_STEM_REACH_MOTIF_MULTIPLE = 2.2` in `bouquetSpine.ts` —
  no connector is drawn beyond that reach. Re-rendered and confirmed
  visually resolved (`after_build023_fixed/darkBotanical_m22-2_detail.png`).
- **Status**: this is a genuine P1-class defect that would have shipped
  had this audit not caught it before commit. It is a caution against
  treating a passing `fragmentedSilhouette` metric alone as sufficient
  evidence of visual quality — exactly this build's own stated premise.

### V-2. Fragmented, "confetti" bouquet silhouette (the brief's named primary defect)
- **Where**: measured by `critic/visualAnalysis.ts`'s `detectFragmentedSilhouette`;
  root-caused (prior session work, `BUILD_023_AUDIT.md` Sections 3-5) to
  `engine/tile.ts`'s Section-10 node-budget thinning pass discarding ~90%
  of raw cluster placements, combined with `heroScatter.ts` never tagging
  cluster identity at all before this build.
- **Evidence**: `luxuryFloral@m22-1` before/after (`reports/build_023/before_after/*/luxuryFloral__luxuryFloral_m22-1_full.png`).
  Numerically: 30-seed matrix rate 100% -> 70% (`reports/build_023/STYLE_DNA_DIAGNOSTIC_MATRIX.json`);
  `darkBotanical` 66.67% -> 6.7%. Both real, substantial, and paired with
  a commercial-score *increase* (not a threshold-gaming decrease).
- **Honest limitation**: the "after" full-tile render still does not read
  as "one dominant visual mass, one clear floral focus" the way the
  brief's own Step 3 (Beautiful Bouquet Composition Engine) demands — it
  reads as *less confetti-like* than before, not yet as a genuinely
  composed bouquet. The strict grid-cell metric and a human's sense of
  "one bouquet" are related but not identical; closing that gap needs the
  hero-scale/negative-space/focal-point work in Steps 2-3, which this
  build did not implement.

### V-3. Thumbnail readability collapses at marketplace scale
- **Where**: no single file — a consequence of `NODE_BUDGET_SAFETY_MARGIN`
  thinning (`engine/tile.ts`) plus the base motif density/scale choices
  in `engine/styleDna.ts`'s per-preset presets.
- **Evidence**: `luxuryFloral@m22-1_128.png` (both before and after) —
  at 128px, the pattern reads as scattered specks with no recognizable
  floral identity or focal point. This is a real, unaddressed gap against
  the brief's own "Thumbnail readability must improve" acceptance target
  (target 8) — this build measured the existing gap but did not build a
  thumbnail-specific legibility pass.

### V-4. Mechanical grid repetition, flat palette, generic silhouettes (Minimal Botanical — untouched by this build)
- **Where**: `layouts/grid.ts` (or the layout `minimalBotanical`'s Style
  DNA selects) for the visible 8-column alignment; `generators/*.ts` for
  the flat black silhouette rendering at this preset's palette settings.
- **Evidence**: `minimalBotanical__minimalBotanical_m22-1_full.png` — an
  unmistakable regular grid of near-identical star/heart/leaf silhouettes,
  entirely monochrome (no color variation visible at all), several
  motifs repeated in near-identical rotation. This directly matches the
  brief's own named defects ("obvious grid alignment," "repeated motif
  rotation," "generic ellipse leaves," "palette that feels flat").
  Confirmed via metrics: `minimalBotanical`'s commercial score is
  byte-identical before/after (44.80 -> 44.80) — this build made zero
  changes here (`minimalBotanical` is not a `premiumHero` style, and none
  of this build's mechanisms touch non-premium presets by design).
- **Status**: real, pre-existing, unaddressed. Flagged as a known
  limitation rather than silently ignored.

### V-5. Unintended scope-leak regression on a non-premium "strong control" preset (FOUND AND FIXED, this audit)
- **Where**: `engine/tile.ts`, `applyBouquetRepairPass` and
  `reserveClusterCompanions` call sites (see Section 2).
- **Evidence**: `strongControl_scandinavianOrganic` commercial score
  86.40 -> 85.00 (before the gating fix), with zero change intended for
  any non-premium preset. Root-caused to the two mechanisms keying off
  `clusterId` presence rather than the `premiumHero` flag, and
  `buildClusterPlacements` tagging `clusterId` unconditionally.
- **Fix**: both call sites now explicitly check `params.premiumHero`.
  Re-measured after the fix: 86.40 -> 86.30 (residual, noise-level).
- **Why this matters**: the brief's own acceptance target 9 ("Strong
  presets must not materially regress") would have been silently
  violated without this specific before/after measurement catching it —
  this is exactly the kind of defect a metrics-only sign-off would miss.

## 4. Categories from the brief's own checklist not separately evidenced above

Several of the brief's named defect categories (weak petal layering,
disconnected stems *within a single motif* as opposed to between cluster
members, awkward tangencies, accidental dense blobs, artificial symmetry,
poor depth, unnatural botanical growth) are properties of the flower/leaf
*generator* geometry (`generators/botanical.ts`) rather than the
composition/placement layer this build touched. This audit did not find
NEW instances of these introduced by this build's changes (verified via
the byte-identical/near-identical before-after comparison for every
non-cluster-affected sample), but it also did not evaluate or improve the
underlying flower/leaf construction quality inherited from Builds
004/005/007/008B — see Known Limitations in `BUILD_023_REPORT.md`.

## 6. Conclusion

This audit found and fixed one real P1 visual defect (V-1, the bare stem
line) and one real regression on a non-premium preset (V-5) that would
otherwise have shipped. It confirms the fragmentation-reduction work is
real, substantial, and paired with genuine commercial-score improvement for
the two most-affected presets. It also honestly documents that the
broader "premium bouquet" visual goal (dominant focal mass, connected
foliage reading as a real bouquet, thumbnail legibility, flower/leaf
anatomy refinement) is **not fully achieved** by this build — see
`BUILD_023_REPORT.md`'s verdict section for how this bears on the
required PASS/FAIL decision.
