## 1. Bugs Fixed (10 of 10 from `UI_BUG_BACKLOG.csv`)

### P0

**BUG-001 — Every freshly-generated Factory package permanently blocked from export.**
Root cause: neither the Factory pipeline (`batch/batchProductionService.ts`) nor the
Autopilot pipeline (`autopilot/generationOrchestrator.ts`) ever wrote a
`generatorVersion` onto the `PortfolioAsset` records they create, so the Commercial
Readiness engine's "Generator completed" check (`commercial/readinessEngine.ts`)
always FAILed — a fundamental blocker with no owner-facing way to fix it.
Fix: both pipelines now pass `generatorVersion` into `catalog/import/importPipeline.ts`'s
`ImportGroupOptions` (a new optional field, defaulting to `null` so manual drag-and-drop
imports are unaffected), reusing the exact `'v1'` literal already used elsewhere in the
codebase as the real generator-version marker (`design-director/handoff/generatorHandoffBuilder.ts`,
`design-director/domain/generatorHandoff.ts`, `autopilot/roleGeneratorHandoff.ts`) — no
new versioning scheme invented.
**Evidence (live browser, before/after):** before — `Generator completed: FAIL — No
generator version recorded on this asset.` (Mission A audit). After —
`Generator completed: PASS — Generated by v1.` Reproduced identically **offline** against
the real production `/studio` build (0 console errors).

### P1

**BUG-002 — "Factory Efficiency 100%" misleading when 0 packages are sellable.**
Fix: relabeled the metric to "Task Completion Rate" in both
`FactoryDashboardPanel.tsx` and `SessionSummaryPanel.tsx`, with a `title` tooltip
clarifying it measures task success, not commercial readiness. The underlying number
is unchanged (per "reuse existing metadata," this is a labeling fix, not a new formula).

**BUG-004 — 9-10 REPAIR-status packages invisible with no destination.**
Fix: added `RepairActivityPanel.tsx`, rendered on Today's Production's Review tab,
listing the current batch's real `repair`-type `FactoryTask` records (the exact same
records `factoryReview.ts`'s `repairCount` already counts) with each one's status and
outcome — no new repair logic, purely a read-only view over existing data.

**BUG-008 — Design Workbench iPad-portrait (834px) layout crushed unreadable.**
Root cause: `DesignWorkbench.tsx` set `grid-template-columns` via an inline `style`
attribute, which — per CSS cascade rules — always wins over the stylesheet's
`@media (max-width: 1100px)` fallback rule that already existed in `workbench.css`
for exactly this case, so the fallback never fired.
Fix: moved the resizable-panel widths into CSS custom properties
(`--wb-left-width`/`--wb-right-width`) set via inline style, and changed
`workbench.css`'s base rule to consume them via `var()` — so the existing media query
(same property, later in the cascade) can override it again. No new responsive logic.

### P2

**BUG-003 — Blocking-reason message duplicated 3× verbatim.**
Fix: `ProductionHomeView.tsx`'s blocked-tasks banner now de-duplicates reasons and
appends a count for each repeated reason instead of concatenating the raw (possibly
repeated) list.

**BUG-005 — Two top-nav buttons permanently highlighted as if both were active.**
Root cause: `ProjectBar.tsx` hardcoded `btn--primary` (the accent/highlighted style)
on "🏭 Today's Production" and "✨ ออกแบบให้ฉันวันนี้" unconditionally — this bar has no
current-view tracking for any button, so having two permanently accented while the rest
were plain read exactly like a broken "2 tabs active" indicator.
Fix: removed the special styling; all `project-bar-btn`s are now visually consistent.

**BUG-006 — 6 of 9 shared-pattern dialogs missing Escape-to-close + focus-into-dialog.**
Fix: added `components/portfolio/useModalDismiss.ts`, a shared hook centralizing the
Escape-key + initial-focus behavior 3 of the 9 dialogs had already hand-written
ad hoc. Applied to the 6 that lacked it: `AssetPreviewDialog`, `MarketplaceSelectionDialog`,
`DownloadCenter`, `SubmissionHistoryPanel`, `PortfolioHealthCheckPanel`,
`PortfolioImportPanel`. The 3 already-working dialogs were left untouched.

**BUG-007 — No `<nav>`/`<main>` landmarks anywhere in the app.**
Fix: wrapped the top navigation (`ProjectBar`) in `<nav aria-label="Main navigation">`
and the entire routed-screen content in one `<main>` in `App.tsx`; removed the
previously-duplicate inner `<main>` (now a plain `<div>` with the same CSS class) to
avoid nested landmarks.

**BUG-010 — Export tab's asset picker defaults to an unrelated older asset.**
Fix: `CommercialPipelineTab.tsx` now selects the asset with the greatest real
`createdAt` among the loaded set as the default, instead of array index 0.

### P3

**BUG-009 — Raw internal-ID slugs shown as the primary asset name.**
Fix: both generation pipelines now pass a human-readable `displayName`
(e.g. `"Pastel Dream Botanical / Floral pattern"`) built from the same
palette/category values `buildFilenameParts()` already computes for the technical
filename — reusing existing data, not inventing new naming logic. The full technical
slug is unchanged in `originalFilename`/`assetId` for anyone who needs it.
