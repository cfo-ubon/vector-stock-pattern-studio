# Build 025 Before/After Summary — Luxury Floral Fragmentation Fix

## Three states compared

This build ended up with three distinct code states for `luxuryFloral`,
not two, because the root cause turned out to be different from what was
first assumed (see `BUILD_025_AUDIT.md` and
`docs/CONNECTIVITY_AWARE_THINNING_REPAIR.md` for the full story):

- **"before" = pre-Build-025 production**: the code as it existed before
  this build started. `fragmentedSilhouette` = 60.67% (300-seed benchmark).
- **"after_fixed" = SHIPPED**: production code with
  `engine/connectivityRepair.ts`'s Connectivity-Aware Thinning Repair now
  active by default for every `premiumHero` style (no flag, no opt-in —
  this is what a user gets today). `fragmentedSilhouette` = **23%**.
- **"after_experimental" = NOT shipped**: the same "before" code plus the
  Luxury Floral Composition Engine (`luxuryComposition: true`, Phases 2-8)
  forced on in-memory. Exists in the repository, fully tested, but not
  reachable through the shipped UI or Style DNA preset — see "Why the
  experimental engine stays disabled" below.

## Why the shipped fix works

The real dominant cause of fragmentation was never cluster-companion
selection (which Build 023's `reserveClusterCompanions` already handled
correctly) — direct instrumentation of real tiles found 92% of isolated
post-thinning instances were `role: 'filler'` ambient-scatter points from
`layouts/heroScatter.ts`'s independent Poisson-disc filler layer, stranded
by a thinning pass whose own distribution grid is coarser than the
critic's fragmentation-detection grid. `connectivityRepair.ts` runs a
post-thinning, pre-render swap-repair pass: for every isolated survivor, it
searches the discarded candidate pool for one that would land adjacent to
it, and swaps it in for a same-role donor — but only ever commits a swap
that a full graph-rebuild simulation proves strictly reduces the real
isolated count. Total kept-instance count (and therefore export node
budget) never changes. See `docs/CONNECTIVITY_AWARE_THINNING_REPAIR.md`
for the complete mechanism and root-cause writeup.

## Why the experimental Composition Engine stays disabled

With the connectivity repair alone already clearing the ≤30% target
(60.67% → 23%), turning on `luxuryComposition` as well only trades a
further, smaller fragmentation gain (23% → 17%) for a `deadSpace` increase
(44.67% → 53.33%) and a commercial-quality drop (80.72 → 78.92) — a trade
this build does not need to make. It remains available for future
targeted work; see `docs/LUXURY_FLORAL_COMPOSITION_ENGINE.md`.

## Visual reading guide

- **`after_fixed` vs `before_production`**: fewer stray single-flower
  "confetti" islands with no neighbor — the ambient filler layer that used
  to strand isolated survivors now gets repaired in place before render,
  consistent with the -37.67pp measured improvement.
- **`after_fixed` vs `after_experimental`**: `after_fixed` keeps the
  original scatter's negative-space balance (dead space essentially
  unchanged from baseline), where `after_experimental` visibly tightens
  bouquet units at the cost of wider empty channels between them.

## Honest disposition

The shipped fix (`after_fixed`) clears the brief's ≤30% mandatory target
with a genuine, tested mechanism, no threshold or diagnostic weakening,
and no regression on `deadSpace`, `tooManyFillers`, or commercial quality.
See `BUILD_025_REPORT.md` for the full verdict.
